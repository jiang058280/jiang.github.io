Coze多Agent模式通过将复杂任务拆解为多个子任务，由不同的Agent分别处理，从而降低单个Agent的复杂度并提升系统可维护性。核心架构分为两层：路由控制节点（负责全局跳转和任务分发）和能力执行节点（负责具体业务逻辑）。执行节点分为两类：工作空间智能体（已发布的独立Bot，可全局复用）和临时内嵌Agent（仅在当前画布生效的轻量单元）。搭建步骤：切换到多Agent模式 → 定义主Agent人设与任务 → 在画布中添加路由节点配置分发规则 → 添加多个执行Agent并分别配置提示词、插件和工作流 → 通过线条连接节点形成协作流程 → 调试测试。核心设计原则是职责单一、模块复用、关注点分离。

### 一、什么是多Agent模式

Coze默认使用单Agent模式，一个机器人仅包含一个处理逻辑。当需求复杂时，单Agent的提示词会变得非常冗长（可能达到几千字），调试困难且难以维护。

多Agent模式允许在一个复合智能体中创建多个独立的Agent节点，每个节点负责一个子任务。**主Agent负责总体的任务管理和协调，多个Miniagent则专注于具体的子任务**，通过协作共同完成复杂的任务。

> **适用场景**：需要处理复杂逻辑的企业级知识库机器人、多角色协作系统等。

### 二、核心架构：画布的两层设计

Coze多Agent画布将所有节点严格分为两大层级：

**① 路由控制节点（全局跳转条件）**
- 只做调度分流，不产生业务回复
- 优先级高于所有Agent自身的触发匹配规则
- **典型使用场景**：用户发送「转人工」直接跳转客服Agent；输入「查余额」直达对应业务Agent

**② 能力执行节点（Agent）**
- 承载具体业务逻辑、回答、工具调用，是“真正干活的单元”
- 分为两类：

| 类型               | 说明             | 特点                                                         |
| ------------------ | ---------------- | ------------------------------------------------------------ |
| **工作空间智能体** | 已发布的独立Bot  | 可全局复用、功能完整（自带工作流、知识库、插件等）、修改原始Bot会联动更新 |
| **临时内嵌Agent**  | 仅在当前画布生效 | 逻辑轻量化、一次性简易子任务单元                             |

### 三、搭建步骤

**步骤1：切换到多Agent模式**
登录Coze → 选择团队空间 → 创建或选择目标机器人 → 在“开发”页面点击“单代理模式”，选择“多代理模式”。

**步骤2：定义角色与任务**
在“开发”面板的“角色和提示”字段中，定义主Agent的角色和要执行的任务。

**步骤3：配置路由节点**
在画布中添加路由控制节点，配置全局跳转条件（如关键词匹配、语义规则），将用户请求分发到对应的Agent。

**步骤4：添加并配置执行Agent**
点击“添加节点”，添加多个Agent节点。为每个Agent配置：
- **独立的提示词**：定义该Agent的角色和职责
- **独立的插件和工作流**：每个Agent可拥有自己的工具集

**步骤5：连接节点形成协作流程**
通过线条连接路由节点和各Agent，定义任务流转路径。

**步骤6：调试与测试**
在右侧“预览”面板中测试机器人，检查运行详情进行调试。

### 四、设计原则与最佳实践

| 原则           | 说明                                                  |
| -------------- | ----------------------------------------------------- |
| **职责单一**   | 每个Agent只负责一个子任务，避免Agent提示词过于臃肿    |
| **模块复用**   | 将通用的Agent发布为“工作空间智能体”，在多个画布中复用 |
| **关注点分离** | 路由层只做分发，执行层只做业务，各司其职              |
| **独立调试**   | 出错时只需修改对应Agent的配置，不影响整体功能         |

多Agent模式将复杂任务分解为一组独立任务，通过**“指挥—调度—执行”的分治架构**，使智能体系统具备可控性、可解释性与可扩展性。
