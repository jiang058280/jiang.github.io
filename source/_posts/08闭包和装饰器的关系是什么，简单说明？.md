## <font color="red">问题: 闭包和装饰器的关系是什么，简单说明？</font>

<details>
<summary><b style="font-size: 1.5rem; color: #2c6b8f;">👇 点击展开/折叠 面试背诵模板（建议先背这个）</b></summary>
    <mymark>
装饰器是闭包最经典的应用场景。闭包提供了“捕获外部变量”的能力，装饰器利用这一能力让内层包装函数（wrapper）能够访问被装饰函数和配置参数，从而在不修改原函数源码的前提下扩展其行为。简言之，闭包是装饰器的底层实现基础，装饰器是闭包在代码增强领域的典型落地。
    </mymark>
</details>

### 从闭包到装饰器的演变

```python
# 阶段1：原始闭包 —— 捕获外部变量 x
def outer(x):
    def inner(y):
        return x + y
    return inner

# 阶段2：闭包捕获函数 —— 把函数当作普通变量捕获
def outer(func):
    def inner(*args, **kwargs):
        print("调用前")        # 增强逻辑
        return func(*args, **kwargs)
    return inner

# 阶段3：加上 @ 语法糖 —— 这就是装饰器
@outer
def target():
    pass
```

### 闭包与装饰器的本质对比

| 维度       | 闭包                                     | 装饰器                               |
| ---------- | ---------------------------------------- | ------------------------------------ |
| 定义       | 内层函数引用外层变量，且外层返回内层函数 | 特殊的闭包，外层接收一个函数作为参数 |
| 捕获内容   | 捕获外层函数的局部变量（数据）           | 捕获被装饰的函数对象（可调用对象）   |
| 核心目的   | 保存状态，延迟计算                       | 增强/扩展函数行为，不改源码          |
| 语法糖支持 | 无                                       | 有 `@deco` 语法糖                    |
| 应用场景   | 工厂函数、数据隐藏、部分应用             | 日志、计时、权限、缓存、路由         |

### 为什么说“装饰器是闭包的应用”？

装饰器的核心机制完全依赖闭包的三要素：
- **外层函数**：接收被装饰函数 `func`（或装饰器参数）
- **内层函数**：`wrapper` 内部调用 `func` 并添加增强逻辑
- **返回内层函数**：将 `wrapper` 返回，替换原函数

```python
def timer(func):               # 外层接收函数 → 闭包要素①
    def wrapper(*args, **kwargs):   # 内层函数 → 闭包要素②
        start = time.time()
        result = func(*args, **kwargs)  # 引用外层变量 func → 闭包要素②（捕获）
        print(time.time() - start)
        return result
    return wrapper             # 返回内层函数 → 闭包要素③
```

### 两者区别的核心要点

| 对比点                 | 闭包                             | 装饰器                             |
| ---------------------- | -------------------------------- | ---------------------------------- |
| 外层参数               | 任意数据（数字、字符串、列表等） | 通常是一个函数或类（可调用对象）   |
| 增强目标               | 无特定增强目标，主要是保存状态   | 专门用于增强/修改目标函数的行为    |
| 语法便利性             | 手动调用外层函数获取内层函数     | 提供 `@` 语法糖简化应用            |
| 是否必须传入可调用对象 | 否                               | 是（装饰器专门针对可调用对象设计） |

### 一句话总结

闭包是装饰器的“发动机”，没有闭包的变量捕获机制，装饰器无法在包装函数中访问到被装饰的原始函数；装饰器则是闭包在代码增强领域的“标准封装”，通过语法糖让闭包的使用更加优雅和规范。
