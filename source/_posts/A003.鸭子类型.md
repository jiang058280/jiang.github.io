## <font color="red">问题: 什么是鸭子类型？</font>

<details>
<summary><b style="font-size: 1.5rem; color: #2c6b8f;">👇 点击展开/折叠 面试背诵模板（建议先背这个）</b></summary>
	<mymark>
鸭子类型是 Python 中的一种编程风格，核心思想是“不检查对象是什么类型，只检查对象能做什么（有没有对应的方法/属性）”。名称源自谚语：“如果它走路像鸭子、游泳像鸭子、叫声像鸭子，那它就是鸭子”。在 Python 中，只要一个对象实现了所需的方法，就可以在期望该方法的任何地方使用，无需显式继承或实现接口。
    </mymark>
</details>

### 鸭子类型 vs 静态类型（对比理解）

| 维度         | 静态类型语言（如 Java） | 鸭子类型语言（如 Python） |
| ------------ | ----------------------- | ------------------------- |
| 类型检查时机 | 编译期                  | 运行时                    |
| 能否调用方法 | 必须显式继承或实现接口  | 只要有方法就能调          |
| 代码风格     | 声明式（需标注类型）    | 隐式（依赖约定）          |
| 核心原则     | “是什么”（is-a）        | “能做什么”（can-do）      |

```java
// Java：必须实现接口才能传入
interface Quackable { void quack(); }
class Duck implements Quackable { ... }
void makeSound(Quackable obj) { obj.quack(); }
```

```python
# Python：只要有 quack() 方法就能用
class Duck:
    def quack(self): print("嘎嘎")
class ToyDuck:
    def quack(self): print("吱吱")  # 不继承任何类
def make_sound(obj):
    obj.quack()          # 只关心对象有没有 quack 方法

make_sound(Duck())      # 嘎嘎
make_sound(ToyDuck())   # 吱吱  ✅ 即使 ToyDuck 和 Duck 毫无继承关系
```

### 实际应用场景（Python 中的体现）

- **内置函数**：`len(obj)` 只要求对象实现 `__len__` 方法，不管是列表、字符串还是自定义类。
- **迭代协议**：`for x in obj` 只要求对象实现 `__iter__` 或 `__getitem__`。
- **上下文管理**：`with obj` 只要求实现 `__enter__` 和 `__exit__`。
- **测试 Mock**：单元测试时用 Mock 对象替换真实对象，只要方法名匹配即可。

### 鸭子类型的优缺点速览

| ✅ 优点                             | ❌ 缺点                                      |
| ---------------------------------- | ------------------------------------------- |
| 代码更灵活，无需依赖复杂的继承体系 | 运行时才发现错误，缺少编译期保护            |
| 减少样板代码，提高开发效率         | 方法名拼写错误会导致难以追踪的 bug          |
| 便于测试（容易 mock）和扩展        | 大型项目中可能降低代码可读性（需依赖文档）  |
| 符合“组合优于继承”的设计原则       | 可能引发 `AttributeError`，需增加防御性代码 |

### 与多态的关系

鸭子类型是 Python 实现多态的核心手段——不是通过继承体系，而是通过方法存在性。不同的类只要有同名方法，就能在同一个函数中互换使用，这比 Java/C++ 的继承多态更灵活，体现了“接口优于实现”的思想。
