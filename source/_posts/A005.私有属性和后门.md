## <font color="red">问题: Python 私有化方法与后门访问</font>

	<mymark>
Python 通过双下划线前缀 `__attr` 实现名称改写（Name Mangling），将属性名变形为 `_ClassName__attr`，以模拟私有化效果，但并非真正的私有（无访问控制机制）。主要作用是防止子类意外覆盖父类属性，约定俗成“不要直接访问”。后门访问指通过变形后的名称 `obj._ClassName__attr` 强行访问，常用于调试或单测，但强烈不推荐在生产代码中使用，破坏了封装意图。真正表示“私有约定”应使用单下划线 `_attr`（PEP 8）。

### 名称改写的底层规则

当在类内部使用 `__attr`（双下划线开头且不以双下划线结尾）时，Python 编译器自动将属性名改写为 `_ClassName__attr`，其中 `ClassName` 为当前类的类名。该改写发生在编译阶段，因此子类中同名的 `__attr` 会被改写为不同的名称，从而实现“隔离”。

```python
class Parent:
    def __init__(self):
        self.__secret = "父类秘密"   # 改写为 _Parent__secret

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__secret = "子类秘密"   # 改写为 _Child__secret

c = Child()
print(c.__dict__)  # {'_Parent__secret': '父类秘密', '_Child__secret': '子类秘密'}
```

### 后门访问的正确姿势与风险

- **语法**：`obj._ClassName__attr` 可绕过“私有”限制，直接访问或修改。
- **用途**：仅限紧急调试、单元测试或特殊框架需求。
- **风险**：依赖“后门”会让代码脆弱，类名或属性变更时后门失效，且破坏封装原则。

```python
class Account:
    def __init__(self):
        self.__balance = 1000

acc = Account()
print(acc._Account__balance)   # 1000（后门访问，不推荐）
acc._Account__balance = 9999   # 强制修改，破坏封装
```

### 单下划线 `_attr` vs 双下划线 `__attr`

| 方式         | 示例        | 效果                              | 用途                                                     |
| ------------ | ----------- | --------------------------------- | -------------------------------------------------------- |
| 单下划线前缀 | `_internal` | 仅命名约定，解释器不做处理        | 表示“保护属性”，告知调用者这是内部细节，外部不应直接使用 |
| 双下划线前缀 | `__private` | 名称改写（`_ClassName__private`） | 防子类意外覆盖，增强隔离性                               |
| 双端双下划线 | `__magic__` | 不改写，保留给 Python 特殊方法    | 魔法方法（如 `__init__`），用户自定义应避免此命名        |

### 最佳实践与设计原则

1.  **默认公开**：Python 信任开发者，无需强制私有。
2.  **用单下划线表达约定**：`_attr` 表示“仅供内部使用”，调用者应尊重此约定。
3.  **双下划线仅用于避免子类冲突**：如父类和子类都有 `__version` 属性，各自独立。
4.  **戒除后门依赖**：除非万不得已（如调试遗留系统），否则不要在生产代码中使用 `_ClassName__attr`。
5.  **面向接口编程**：设计良好的公开接口（方法）来操作内部状态，比依赖“私有”属性更健壮。
