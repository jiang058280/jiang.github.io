### 一、基本概念

提示词链是一种任务编排策略，通过将复杂任务拆解为多个子任务，每个子任务对应一次独立的LLM调用，前一步的输出作为后一步的输入，形成“链式”组合来最终完成任务。它不是简单的多次对话，而是有明确数据流转和步骤依赖的工程化方法。

### 二、为什么需要提示词链

| 问题      | 单次Prompt的局限                     | 提示词链的解决方案                      |
| --------- | ------------------------------------ | --------------------------------------- |
| 复杂任务  | 一次生成认知负载重，易遗漏关键点     | 拆分为多步，每步专注单一子任务          |
| 错误定位  | 难以判断哪部分出错                   | 每步输出可审计，快速定位问题步骤        |
| Token成本 | 单次Prompt可能臃肿，含大量示例和规则 | 每步仅包含必要上下文，合计Token通常更少 |
| 可维护性  | 提示词庞大，修改风险高               | 每步独立，可单独优化和替换              |

### 三、核心工作机制

① **任务拆解**：将最终目标拆解为3-7个可独立执行的子任务。② **依赖分析**：确定哪些子任务必须在其他之前完成，哪些可并行执行。③ **逐步调用**：按依赖顺序执行，每步独立调用LLM，前一步输出作为下一步上下文。④ **汇总整合**：最后一步将各子任务结果整合为最终答案输出。

### 四、常见链条结构

- **线性链**：A→B→C→D，前一步输出是下一步输入，适用于“计划→检索→分析→撰写”流程。
- **并行链**：多个独立子任务同时执行后汇总，适用于从不同维度分析同一问题（如同时获取用户画像、市场数据、竞品信息）。
- **条件分支链**：根据中间结果选择下一步路径，如“若情感极性为负面，则执行A；否则执行B”。

### 五、Prompt Chain vs CoT vs ReAct

| 技术     | 本质                       | 适用场景                               |
| -------- | -------------------------- | -------------------------------------- |
| 提示词链 | 工程拆分（多次调用串联）   | 复杂任务、多文档处理、需要中间结果审计 |
| 思维链   | 推理分解（单次调用内分步） | 数学题、逻辑推理、多步决策             |
| ReAct    | 推理+行动交替（Agent循环） | 需要调用外部工具、信息检索、动态决策   |

提示词链是**任务编排**层面的技术，思维链是**推理引导**层面的技术，两者可协同使用（提示词链中每步可嵌入思维链）。

### 六、设计原则与最佳实践

- **每步只做一件事**：单一职责，避免单步内塞入多个隐含子任务。
- **输出格式结构化**：要求每步输出JSON或特定标记格式，便于解析和传递。
- **预留人工介入节点**：关键决策点设置人工确认或修正环节。
- **中间结果可缓存**：不变数据缓存，避免重复调用，节省成本和延迟。
- **Fallback策略**：某步失败时有备选路径，整链不崩溃。

### 七、典型应用场景

- **长文档摘要**：分块摘要→聚合摘要→全局摘要
- **智能客服**：意图识别→信息检索→答案生成→审核校验
- **研究分析**：计划制定→数据收集→分析推理→报告撰写
- **简历筛选**：解析→技能提取→匹配评分→排序推荐

### 八、核心总结

提示词链的本质是将“人做复杂任务时的分步思维”迁移到LLM调用流程中，通过工程化的拆分、编排和组合，让模型在每一步专注于单一子任务，最终输出高质量的结果。其设计核心是“让每一步都简单到模型不可能犯错”，当单次调用足够简单时，输出质量和稳定性自然提升。
